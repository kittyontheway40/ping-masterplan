# ระบบติดตามแผนงานโครงการ แผนแม่บทลุ่มน้ำปิง

เว็บสำหรับค้นหาและตรวจสอบแผนงานโครงการรายยุทธศาสตร์ของแผนแม่บทการบริหารจัดการทรัพยากรน้ำ ลุ่มน้ำปิง มี 4 หน้า

1. **โครงการรายตำบล** (6 จังหวัด, 49 อำเภอ, 336 ตำบลตามพระราชกฤษฎีกากำหนดลุ่มน้ำ)
2. **โครงการรายลุ่มน้ำสาขา** (30 ลุ่มน้ำสาขา)
3. **แผนที่** (ตำบล ลุ่มน้ำสาขา ลำน้ำ และภูมิประเทศจาก DEM)
4. **ผู้ดูแลระบบ** (กล่องรอพิจารณา, แก้ไข/ลบโครงการ, ประวัติการแก้ไข, ส่งออก Excel)

สิทธิ์การใช้งาน
- **ทุกคน** เปิดดูได้โดยไม่ต้องล็อกอิน และเสนอโครงการใหม่ได้ โครงการที่เสนอจะเข้า "กล่องรอพิจารณา" ก่อน
- **ผู้ดูแลระบบ** ต้องล็อกอินด้วยอีเมลและรหัสผ่าน จึงจะอนุมัติ/ไม่อนุมัติ แก้ไข หรือลบโครงการได้ ทุกการกระทำถูกบันทึกในประวัติ

## โครงสร้างไฟล์

```
index.html            หน้าเว็บ
config.js             ค่าเชื่อมต่อ Firebase (ถ้าว่าง = โหมดทดลอง)
assets/app.js         โปรแกรมหลัก
assets/style.css      หน้าตา (โทนน้ำเงินหน่วยงาน + ชมพูลุ่มน้ำปิงเป็นจุดเน้น)
data/master.json      ยุทธศาสตร์ แผนงาน มาตรการ ตัวชี้วัด กลุ่มพื้นที่ ลุ่มน้ำสาขา ตำบล
data/projects_seed.json  808 แนวทาง/โครงการตั้งต้นจาก Excel
data/*.geojson        ขอบเขตตำบล ลุ่มน้ำสาขา จังหวัด ลำน้ำ (ย่อขนาดแล้ว)
data/hillshade.webp   ภาพภูมิประเทศ (สีตามความสูง + เงา) จาก DEM
data/amphoe.geojson   ขอบเขตอำเภอ (รวมจากขอบเขตตำบล)
firestore.rules       กฎความปลอดภัยของฐานข้อมูล
tools/build_data.py   สคริปต์สร้างไฟล์ใน data/ ใหม่จาก Excel + GeoPackage
```

## ขั้นที่ 1 · ขึ้นเว็บด้วย GitHub Pages (ฟรี)

1. สร้าง repository ใหม่ใน GitHub เช่น `ping-masterplan` (เลือก Public หรือ Private ก็ได้ แต่ Pages แบบฟรีต้องเป็น Public)
2. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ (Add file › Upload files แล้วลากทั้งโฟลเดอร์)
3. ไปที่ **Settings › Pages** เลือก Source = *Deploy from a branch*, Branch = `main` / `(root)` แล้วกด Save
4. รอ 1–2 นาที จะได้ลิงก์ `https://<ชื่อบัญชี>.github.io/ping-masterplan/`

ถึงขั้นนี้เว็บใช้ได้แล้ว แต่ยังไม่เชื่อมฐานข้อมูลออนไลน์ (จุดสีเทาหน้าเลขเวอร์ชัน) (ข้อมูลที่เพิ่มเก็บในเบราว์เซอร์ของแต่ละคน ยังไม่แชร์กัน รหัสผู้ดูแลทดลอง `admin1234`)

## ขั้นที่ 2 · เปิดฐานข้อมูลออนไลน์ด้วย Firebase (ให้ทุกคนเห็นข้อมูลเดียวกัน)

1. เข้า https://console.firebase.google.com › **Add project** (ตั้งชื่อ เช่น `ping-masterplan`) ปิด Google Analytics ได้
2. **Build › Firestore Database › Create database** เลือก location `asia-southeast1 (Singapore)` › Production mode
3. แท็บ **Rules** ลบของเดิม วางเนื้อหาจากไฟล์ `firestore.rules` แล้ว **Publish**
4. **Build › Authentication › Get started › Sign-in method** เปิด **Email/Password**
5. **Authentication › Settings › Authorized domains** เพิ่ม `<ชื่อบัญชี>.github.io`
6. **Project settings (รูปเฟือง) › General › Your apps › Web (</>)** ตั้งชื่อแอป จะได้ค่า `firebaseConfig` นำมาใส่ใน `config.js`

```js
firebase: {
  apiKey: "AIza...",
  authDomain: "ping-masterplan.firebaseapp.com",
  projectId: "ping-masterplan",
  storageBucket: "ping-masterplan.appspot.com",
  messagingSenderId: "...",
  appId: "..."
}
```
   ค่าเหล่านี้เปิดเผยได้ ความปลอดภัยอยู่ที่ `firestore.rules` และระบบล็อกอิน

7. อัปโหลด `config.js` ที่แก้แล้วขึ้น GitHub แทนไฟล์เดิม จุดหน้าเลขเวอร์ชันมุมขวาบนจะเปลี่ยนจากสีเทาเป็นสีเขียว

## หน้าเข้าใช้งาน (เด้งขึ้นครั้งแรก)

เปิดเว็บครั้งแรกจะมีหน้าต่างให้เลือก 2 แบบ
- **ผู้ใช้ทั่วไป**: กดแล้วเข้าได้ทันที ไม่ต้องกรอกอะไร (ดูข้อมูลและเสนอโครงการได้ แต่เข้าหลังบ้านไม่ได้)
- **ผู้ดูแลระบบ**: ต้องใส่รหัสผู้ดูแล

ระบบจำการเลือกไว้ในเครื่องนั้น 30 วัน (ผู้ดูแลเลือกได้ว่าจะให้จำหรือไม่) ผู้ใช้ทั่วไปเปลี่ยนเป็นผู้ดูแลได้จากปุ่มมุมขวาบน

**รหัสผู้ดูแล** ในไฟล์ `config.js` เก็บเป็นค่า SHA-256 (`adminCodeHash`) ไม่ได้เก็บรหัสจริง เปลี่ยนรหัสได้โดยแปลงรหัสใหม่เป็น SHA-256 แล้ววางแทน

> ข้อควรรู้: ก่อนเชื่อม Firebase การตรวจรหัสทำในเบราว์เซอร์ เหมาะกับช่วงทดลอง เมื่อเชื่อม Firebase แล้วให้ใช้วิธีด้านล่าง การตรวจรหัสจะทำที่เซิร์ฟเวอร์ Google และกฎ `firestore.rules` จะกันไม่ให้คนที่ไม่ใช่ผู้ดูแลเขียนข้อมูลได้จริง

**ใช้รหัสเดียวร่วมกัน (แบบง่าย)**: สร้างบัญชีกลาง 1 บัญชีใน Authentication เช่น `admin@ping-plan.app` ตั้งรหัสผ่านเป็นรหัสผู้ดูแล เพิ่ม UID ของบัญชีนี้ใน `admins` แล้วใส่อีเมลนี้ที่ `adminEmail` ใน `config.js` หน้าเข้าใช้งานจะถามแค่รหัส

**แยกบัญชีรายคน (แนะนำเมื่อขึ้นระบบจริง)**: เว้น `adminEmail` ว่าง หน้าเข้าใช้งานจะถามอีเมล + รหัสผ่าน และประวัติการแก้ไขจะบอกชื่อผู้แก้รายคน ทำตามขั้นที่ 3

## ขั้นที่ 3 · ระบบรหัสผู้ดูแล (Admin)

ใช้ **Firebase Authentication** แทนการฝังรหัสไว้ในหน้าเว็บ เพราะรหัสที่ฝังในโค้ดใครก็เปิดดูได้

- ผู้ดูแลแต่ละคนมี **บัญชีของตัวเอง** (อีเมล + รหัสผ่าน) จึงรู้ว่าใครแก้อะไรเมื่อไร
- Google เก็บรหัสแบบเข้ารหัส ผู้พัฒนาก็มองไม่เห็นรหัส
- ลืมรหัส กด "ลืมรหัสผ่าน" ในหน้าล็อกอิน ระบบส่งลิงก์ตั้งใหม่ทางอีเมล
- การมีบัญชีอย่างเดียวยังไม่ใช่ผู้ดูแล ต้องอยู่ในรายชื่อ `admins` ด้วย (สองชั้น)

**วิธีเพิ่มผู้ดูแล 1 คน**
1. Authentication › Users › **Add user** ใส่อีเมลและรหัสผ่านเริ่มต้น (อย่างน้อย 8 ตัว แนะนำ 12 ตัวขึ้นไป)
2. คัดลอก **User UID** ของคนนั้น
3. Firestore › **Start collection** ชื่อ `admins` › Document ID = UID ที่คัดลอก › ใส่ฟิลด์ `name` (ชื่อ) และ `org` (หน่วยงาน)
4. แจ้งอีเมล/รหัสเริ่มต้นให้ผู้ดูแล และให้เปลี่ยนรหัสด้วย "ลืมรหัสผ่าน" ครั้งแรก

**ถอนสิทธิ์** ลบเอกสารของคนนั้นใน `admins` (หรือ Disable user ใน Authentication)

## ขั้นที่ 4 · นำเข้าข้อมูลตั้งต้น 808 โครงการ (ทำครั้งเดียว)

ล็อกอินผู้ดูแล › หน้า **ผู้ดูแลระบบ** › กด **นำเข้าข้อมูลตั้งต้น** ระหว่างที่ฐานข้อมูลยังว่าง หน้าเว็บจะแสดงข้อมูลจาก Excel แบบอ่านอย่างเดียวไปก่อน

## ขั้นตอนการทำงานของโครงการใหม่

```
ผู้ใช้กด "+ เสนอโครงการ" › กรอกฟอร์ม › ส่ง
        ↓  (เก็บใน submissions — คนทั่วไปมองไม่เห็น)
ผู้ดูแลเห็นในกล่องรอพิจารณา › อนุมัติ / ตรวจแก้ก่อนอนุมัติ / ไม่อนุมัติ (ใส่เหตุผล)
        ↓  อนุมัติ
บันทึกลง projects พร้อมรหัสใหม่ (P0809, P0810, …) ทุกคนเห็นทันที + บันทึกประวัติ
```

ฟิลด์ในฟอร์ม: ผู้เสนอ/หน่วยงาน/ช่องทางติดต่อ · ลุ่มน้ำสาขา* · ยุทธศาสตร์* · แผนงาน F* · มาตรการ S* (กรองตามกันอัตโนมัติ) · ชื่อแนวทาง/โครงการ* · รายละเอียด · ตำบลเป้าหมาย* (เลือกได้หลายตำบลในลุ่มน้ำสาขานั้น หรือเลือก "ไม่มีตำบลเป้าหมาย") · กลุ่มพื้นที่ (คำนวณจากตำบลที่เลือก) · หน่วยงานรับผิดชอบ · งบประมาณ · ปีเริ่ม–สิ้นสุด · สถานะ · ตารางอ้างอิง · หมายเหตุ

## ย้ายไปโดเมนของหน่วยงานภายหลัง

เว็บเป็นไฟล์ static ทั้งหมด จึงย้ายได้ง่าย
- **ถ้าใช้ Firebase ต่อ**: คัดลอกทั้งโฟลเดอร์ไปวางบนเว็บเซิร์ฟเวอร์ของหน่วยงาน แล้วเพิ่มโดเมนใหม่ใน Authorized domains
- **ถ้าหน่วยงานต้องเก็บข้อมูลบนเซิร์ฟเวอร์ตัวเอง**: แก้เฉพาะส่วน `Store` ใน `assets/app.js` ให้เรียก API ของหน่วยงาน ส่วนหน้าจอไม่ต้องแก้ และส่งออกข้อมูลทั้งหมดได้จากปุ่ม "ส่งออกโครงการเป็น Excel"

## อัปเดตข้อมูลตั้งต้นจาก Excel/GIS ชุดใหม่

วางไฟล์ไว้ในโฟลเดอร์ `source/` ตามชื่อนี้: `plan.xlsx`, `basin_decree.xlsx`, `tambon_ping.gpkg`, `subbasin_ping.gpkg`, `province_ping.gpkg`, `ping_mainriver.gpkg` แล้วรัน

```
pip install geopandas pyogrio openpyxl
python tools/build_data.py source/
python tools/build_map_extras.py source/   # ต้องมี Dem_ping.tif ด้วย
```

หมายเหตุ: ถ้านำเข้าข้อมูลตั้งต้นลง Firebase ไปแล้ว การแก้ `projects_seed.json` จะไม่เปลี่ยนข้อมูลออนไลน์ ให้แก้ผ่านหน้าผู้ดูแลแทน
